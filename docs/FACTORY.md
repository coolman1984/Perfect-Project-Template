# The Excel Automation Project Factory

How a non-technical employee turns Excel files and business knowledge into a
working automation, and what the Factory does automatically along the way.

```text
THE USER PROVIDES BUSINESS KNOWLEDGE.
THE TEMPLATE STEERS THE AI AGENT.
THE AGENT IMPLEMENTS WITHIN CONTROLLED BOUNDARIES.
MACHINE GATES VERIFY THE RESULT.
THE USER APPROVES BUSINESS MEANING AND RESULTS.
```

## The employee's flow

```text
PROJECT_TOOL factory new       --id <report> --title "..."
PROJECT_TOOL factory interview --id <report> --question <id> --answer "..."
PROJECT_TOOL factory review    --id <report>          # Understanding Review
PROJECT_TOOL factory approve   --id <report> --decision <d> --by "Name" \
                                --method wizard_confirmation --evidence "..."
PROJECT_TOOL factory generate  --id <report> --title "..."
PROJECT_TOOL factory brief     --id <report>          # hands off to the agent
PROJECT_TOOL factory status    --id <report>          # project health
```

No question ever names a technical concept. "What does one row represent?"
stands in for grain; "Can records be corrected later?" stands in for load
mode. See `factory/questionnaire.py` for the full translation table.

## The Golden Reference

`reports/_REFERENCE/` is a complete, working report over synthetic fixtures
(`tests/fixtures/reference/`). It is not documentation of a pattern — it is the
pattern, executed and verified against hand-derived answers frozen in
`tests/expected/reference/expected.json`.

Run it: `PROJECT_TOOL factory reference verify` (needs DuckDB — an
application-tier locked component, `pip install duckdb`).

A new report is generated by copying this shape and configuring it — see
`factory/generator.py`. `tests/factory/test_factory_flow.py` fingerprints
every Factory Core file before and after generating a report and fails the
build if generation touched a single byte of the shared engine.

## Human approval, honestly

`factory/approvals.py` documents the trust model in full. Short version: every
approval binds to a hash of the exact value approved, so changing the
configuration afterwards automatically voids it. An agent's identity is
checked and refused (`ai`, `agent`, `claude`, `assistant`, `bot`, …). This
detects forgery in review; it is not cryptographic proof against a hostile
agent with write access to the same workspace. For that, pair it with a
human-reviewed pull request, a signed artifact, or a company approval
workflow — see the module docstring.

## What the agent receives

After enough of the interview is approved, `factory brief` writes
`.ai/BUILD_BRIEF.md`: the approved contract, what remains pending, the
variation points to configure, the Factory Core boundary not to touch, and the
tests and gates the work must pass. No raw business rows.
