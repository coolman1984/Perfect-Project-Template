## What the system understood

| Item | Understanding | What this means |
|---|---|---|
| One record | One downtime event on one line on one date | What one row in your file represents |
| New files | New files add records and update ones that were corrected. | How new files join your existing history |
| Unique record | event_date + line + event_id | The columns that identify one record |
| Main accuracy check | Total downtime minutes | The number we compare between your file and the system |
| Dashboard decision | Which line loses the most time this week | The decision this dashboard supports |
| Missing records | Keep the record unchanged. | What it means when a record stops appearing |
| Data storage | D:/secure/downtime | Where the extracted data may live |
| Approved by | Maintenance Lead - Sara Ahmed | Who owns the meaning of this report |

## Approval record

Approvals live in `factory/approvals/line_downtime.approvals.jsonl`,
each bound to a hash of the exact approved value. If a value changes after
approval, the approval stops counting and the item returns to
`NEEDS YOUR APPROVAL`.

Run `PROJECT_TOOL factory status --id line_downtime` to see the current
state of every decision.
